TRADE-OFF DECISIONS
Architecture decisions

3 Trade-off Justifications

Async vs Sync

Chọn Event-Driven Async (S3 → Lambda) thay vì xử lý trực tiếp trên API Gateway để giải quyết giới hạn timeout 29s. Đổi lại Frontend phải Polling.

DynamoDB vs RDS

Chọn DynamoDB PAY_PER_REQUEST để scale-to-zero tiết kiệm chi phí. Đổi lại không hỗ trợ query quan hệ phức tạp.

No NAT Gateway

VPC Interface Endpoints cho Bedrock & Textract, tiết kiệm $32/tháng NAT Gateway. Đổi lại chỉ gọi được services hỗ trợ PrivateLink.

COST OPTIMIZATION
Savings strategies

Chiến lược tối ưu chi phí

Lambda

Smallest memory meeting latency. Provisioned concurrency chỉ khi cần. Timeout sát expected max.

DynamoDB

PAY_PER_REQUEST tránh over-provisioning. TTL auto-expire stale items.

S3

Lifecycle rules: IA @30d, delete @90d. OAC giảm extra S3 request costs.

VPC Endpoints

Chỉ dùng cho required services (Bedrock, Textract). Delete unused endpoints.

Textract

Local PDF parsing first → giảm ~80% Textract calls. Cap MAX_TEXTRACT_CALLS_PER_DAY.

Budget Alerts

Alerts at 50% & 80% thresholds. Cost Anomaly Detection spot spikes early.
